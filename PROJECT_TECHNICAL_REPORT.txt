3.8 STATE MANAGEMENT (Context API)
------------------------------------------------------------------------------
  AUTH CONTEXT (AuthContext.tsx):
    State:
      user: User | null          - Current user object
      token: string | null       - JWT access token
      isLoading: boolean         - Initial auth check loading
      isAuthenticated: boolean   - Derived from user && token
    Actions:
      login(email, password)     - POST /auth/login, stores token+user
      register(username, email,  - POST /auth/register, then auto-login
                 password)
      logout()                   - POST /auth/logout, clears localStorage
      setUser(user)              - Manual user update
    Persistence: localStorage (keys: 'token', 'user')
    Auto-restore: On mount, checks localStorage

  THEME CONTEXT (ThemeContext.tsx):
    State:    theme ('light' | 'dark')
    Actions:  toggleTheme()
    Config:   defaultTheme='light', switchable=true
    Persistence: localStorage, applies 'dark' class to <html>

  I18N CONTEXT (I18nContext.tsx):
    State:      language ('en' | 'zh')
    Actions:    setLanguage(lang), t(key) -> translated string
    Structure:  Dot-notation key lookup (e.g., t('nav.home'))
    Languages:  English (en), Chinese (zh)
    Categories: nav, home, auth, editor, common, ...

3.15 AUTHENTICATION FLOW (Client-Side)
------------------------------------------------------------------------------
  REGISTER:
    1. Form validates fields (real-time)
    2. AuthContext.register(username, email, password)
    3. api.authAPI.register() -> POST /api/auth/register
    4. On success: auto-login (same credentials)
    5. Token + user stored in localStorage
    6. isAuthenticated = true

  LOGIN:
    1. Form validates email + password
    2. AuthContext.login(email, password)
    3. api.authAPI.login() -> POST /api/auth/login
    4. Backend returns { access_token, user }
    5. Token stored in localStorage as 'token'
    6. User stored in localStorage as 'user' (JSON)
    7. State: user, token, isAuthenticated = true

  TOKEN AUTO-RESTORE:
    On mount, AuthProvider checks localStorage
    If token + user found (valid JSON), restores auth state
    No token refresh mechanism (relies on 24h JWT expiry)

  LOGOUT:
    1. AuthContext.logout()
    2. api.authAPI.logout() -> POST /api/auth/logout (silent on error)
    3. Clears localStorage 'token' and 'user'
    4. State: user=null, token=null, isAuthenticated=false

  ROUTE PROTECTION:
    ProtectedRoute component:
      isLoading=true  -> full-screen Loader
      !authenticated  -> redirect /login
      adminRequired & !admin -> redirect /
      otherwise       -> render children

4.7 AUTHENTICATION & AUTHORIZATION
------------------------------------------------------------------------------
  REGISTRATION:
    - Email validation (regex)
    - Password minimum length: 6 characters
    - Username/email uniqueness check
    - Creates User + Profile records
    - Supports admin user creation (is_admin flag in body)

  LOGIN:
    - Email + password verification
    - Checks is_active flag (banned users cannot login)
    - Returns JWT access token + user data

  JWT CONFIGURATION:
    - Token in Authorization: Bearer header
    - 24-hour expiry
    - Identity: user ID (converted to string)

  LOGOUT:
    - Token blacklisting via TokenBlacklist table
    - JTI (JWT ID) extracted and stored
    - Blocked on every request via token_in_blocklist_loader

  AUTHORIZATION:
    - @jwt_required() decorator for protected endpoints
    - admin_only: checks user.role == 'admin'
    - Owner checks: blog.user_id == current_user_id
    - Optional JWT: verify_jwt_in_request(optional=True) for mixed endpoints

4.10 AI INTEGRATION
------------------------------------------------------------------------------
  AI Service: app/ai/analyzer.py (AIService class)

  Configuration:
    OPENAI_API_KEY  -> OpenAI client (gpt-3.5-turbo)
    IMAGE_API_KEY   -> Image generation (DALL-E 3)
    Auto-detects: use_mock=True if key is empty/missing

  FEATURES:

  1) analyze_content(title, content):
     Mock mode:
       - Quality: word count based (0-100)
       - Readability: avg sentence length based (0-100)
       - Grammar: rule-based feedback
       - SEO: keyword/tip-based feedback
     OpenAI mode:
       - Uses gpt-3.5-turbo with structured JSON prompt
       - Returns quality_score, readability_score, grammar_feedback,
         seo_feedback

  2) fact_check_content(title, content):
     Mock mode:
       - Checks against 19 fake-news keywords
       - 3 sensational patterns (regex: ALL CAPS, !!!, ???)
       - Capitalization/exclamation ratios
       - Source citations check
       - Absolute claims detection (e.g., "100%", "never", "always")
       - Score: 0-100, threshold < 40 = fake news flag
       - Returns: credibility_score, is_fake_news, red_flags[],
         warnings_count, feedback
     OpenAI mode:
       - Uses gpt-3.5-turbo with detailed fact-checking prompt
       - Checks: unverified claims, clickbait, conspiracy theories,
         medical misinformation, etc.

  3) generate_content(prompt):
     Mock mode:
       - 7-paragraph structured essay with title, excerpt, full content
     OpenAI mode:
       - Uses gpt-3.5-turbo with strict JSON output
       - Returns {title, excerpt, content}

  4) generate_image(prompt):
     Mock mode:
       - Returns placeholder from via.placeholder.com
     OpenAI mode:
       - Uses dall-e-3 via openai.Image.create()
       - Returns image URL

  Persistent AI Data:
    Analysis results can be saved to AIAnalysis model (linked to blog)
    Fact-check results stored in AIAnalysis: credibility_score,
      is_fake_news, fact_check_feedback

4.15 SECURITY MEASURES
------------------------------------------------------------------------------
  1. Password hashing: bcrypt (Flask-Bcrypt) with salts
  2. JWT authentication: 24h expiry, token blacklisting on logout
  3. SQL injection prevention: SQLAlchemy ORM parameterized queries
  4. Input validation:
     - Email regex validation
     - Password minimum length (6 chars)
     - Required field checks
     - File extension whitelist
  5. File upload security:
     - Extension whitelist (png, jpg, jpeg, gif, webp)
     - UUID-based filenames (no user-controlled names)
     - Max file size: 16MB
     - secure_filename() from werkzeug
  6. Authorization checks:
     - Owner-only resource modification
     - Admin-only sensitive operations
     - Role-based access control
     - Cannot follow self
     - Cannot delete own admin account
  7. Account management: Deactivation toggle
  8. CORS: enabled via Flask-CORS
  9. JWT blacklisting for logout
  10. Environment isolation (.env in .gitignore)

5.3 MIGRATION SCRIPTS
------------------------------------------------------------------------------
  ORDER: schema.sql -> migration_v2.sql -> migration_image_storage.sql
         -> migration_fact_check.sql (or quick_fix_migration.sql)

  1. schema.sql
     - Creates database 'blog_platform' (USE blog_platform)
     - Creates 7 tables: users, profiles, blogs, ai_analysis, comments,
       likes, bookmarks
     - Inserts seed data (2 users, 2 profiles, 2 blogs, 2 ai_analysis,
       2 comments, 2 likes)
     - NOT idempotent (no IF NOT EXISTS)

  2. migration_v2.sql
     - Adds 5 tables: follows, comment_likes, reports, platform_settings,
       token_blacklist
     - Inserts 6 default platform settings
     - IS idempotent (CREATE TABLE IF NOT EXISTS + INSERT IGNORE)

  3. migration_image_storage.sql
     - ALTER blogs.image_url -> VARCHAR(500)
     - ALTER profiles.avatar_url -> VARCHAR(500)
     - NOT idempotent

  4. migration_fact_check.sql
     - ALTER blogs ADD is_fake_news BOOLEAN
     - ALTER ai_analysis ADD credibility_score, is_fake_news,
       fact_check_feedback
     - CREATE INDEX idx_is_fake_news
     - NOT idempotent (will error if columns exist)

  5. quick_fix_migration.sql (alternative to migration_fact_check.sql)
     - Same changes but uses INFORMATION_SCHEMA.COLUMNS checks
     - Dynamic SQL with @sql
     - IS idempotent (safe to run multiple times)

  6. backend/run_migration.py (alternative to both fact-check SQLs)
     - Python script using pymysql
     - Reads database URL from .env
     - Idempotent (INFORMATION_SCHEMA checks)
     - Updates NULL -> FALSE for is_fake_news columns
     - Outputs DESCRIBE results

6.1 USER REGISTRATION

6.2 BLOG CREATION WITH AI
------------------------------------------------------------------------------
  CreateBlog.tsx
  -> Option A: Upload cover image (POST /api/upload/image)
  -> Option B: Generate cover image (POST /api/ai/generate-image)
  -> User writes content
  -> AI Content Review (POST /api/ai/analyze)
  -> AI Fact-Check (POST /api/ai/fact-check)
  -> AI Writing Assistant (POST /api/ai/generate)
  -> Save Draft / Publish (POST /api/blogs)
  -> If AI analysis requested: saved to ai_analysis table

6.3 ADMIN MODERATION
------------------------------------------------------------------------------
  Admin login -> JWT with admin role
  GET /api/admin/stats     -> Dashboard charts
  GET /api/admin/users     -> User management table
  PUT .../toggle-active    -> Ban/unban user
  PUT .../role             -> Change to admin/user
  GET /api/admin/blogs     -> Blog moderation list
  POST .../approve         -> status='published'
  POST .../reject          -> status='rejected'
  GET /api/admin/reports   -> Content reports
  POST .../resolve         -> status='resolved'/'dismissed'
  GET/PUT /api/admin/settings -> Platform configuration

6.4 TRENDING COMPUTATION
------------------------------------------------------------------------------
  GET /api/trending/topics:
    SELECT tags, score=COUNT*10 + SUM(views)*2 + SUM(likes)*5
    + SUM(comments)*3
    GROUP BY tags, ORDER BY score DESC, LIMIT 10

  GET /api/trending/authors:
    Score = blogs*15 + views*1 + likes*8 + comments*5 + followers*20
    Real-time query, no caching

6.5 SEARCH
------------------------------------------------------------------------------
  GET /api/search?q=<query>:
    - FULLTEXT MATCH on blogs.title + blogs.content
    - LIKE search on users.username + users.email
    - Returns {blogs[], users[]}
